# Owl

A mobile-first PWA for reading **text-layer PDF** books on iPhone, with **tap-to-lookup**: select a name or place, tap the floating _Look up_ pill, and get a photo, a 2–3 sentence summary and a map in a drawer, without leaving the book.

Everything runs in the browser. Books, reading positions and past lookups are stored on the device in IndexedDB; there is no backend and no account.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type-check + production build into dist/
npm run preview    # serve dist/ (service worker enabled)
npm run check      # ESLint + tsc --noEmit + Prettier check
npm run test:e2e   # Playwright suite (builds, serves on :4173, emulated iPhone 14 in Chromium)
```

**Tests:** `tests/e2e/` covers import/reopen/progress, legacy records, Pages↔Scroll and rotation restore, zoom, dark mode, Dark/Black keeping photos' colours while charts and full-page scans invert, the Black theme's chrome, the live scrubber, all three lookup modes, disambiguation, offline cache hits, Refresh, 503 Retry, the Storage sheet, focus trapping and reduced motion, the search bar, context chips, section snippets, the Google link, and X-Ray (page list, Off, whole-book index across reloads, In This Book jump and return, index deleted with its book), and Clip & Export (cross-page handles, no export code loaded while reading, the page-break void removed from the PNG, a 2-page cropped PDF that's still searchable, a 1-page clean PDF, Markdown with de-hyphenation, headings, lists and citation, saving / jumping / deleting clips, and clips deleted with their book). Wikipedia is mocked with route handlers, and the fixtures `atlas.pdf` (300 pages) `chronicle.pdf` (12 pages of prose with names, running headers and a paragraph across a page break) and `figures.pdf` (a photo, a chart, a rotated photo and a full-page scan) are regenerated by `make-atlas.py`, `make-chronicle.py` and `make-figures.py` (reportlab). It's Chromium emulation, not WebKit: native iOS behaviour still needs a device. `.github/workflows/ci.yml` runs check, build and the suite on every pull request.

To try it on an iPhone, open the deployed site in Safari, then _Share → Add to Home Screen_.

**GitHub Pages:** `.github/workflows/deploy-pages.yml` builds every push to `main` with `BASE=/owl/` (the Vite base, the PWA manifest `scope`/`start_url` and the service worker path all follow it) and pushes the built site to the `gh-pages` branch. One-time setup: _Settings → Pages → Source: Deploy from a branch → Branch: `gh-pages`, folder `/ (root)`_. Don't point Pages at `main`: that serves the unbuilt source and shows a blank page.

Other static hosts (Vercel, Netlify) serve from `/`, so a plain `npm run build` is right there.

Notes:

- **Reading position** is saved through one debounced `onProgressChange` funnel in `ReaderShell`, and flushed when the app is backgrounded. It stores the page and zoom.
- **Rotation** never resets the position: the PDF view keeps its page and its zoom relative to fit-width.
- **Smooth scrolling on iPhone**: PDF paging is a CSS scroll-snap carousel and Scroll mode is a plain vertical scroller, so swipes and momentum run on the compositor. pdf.js work is queued for when scrolling stops. Pinch-zoom previews with a GPU transform and re-renders once at the end.
  - _Two-pass canvases_: pages first render at ≤2× DPR / 2.2 MP; the current page gets a sharp pass (full DPR, ≤4.5 MP) after 300 ms of stillness.
  - _Lazy page sizes_: only page 1 and the start page are measured on open; real sizes for current ± 20 pages are probed while idle, and the restore effect keeps the reading position fixed when a page above changes height.
  - _Virtualized Scroll mode_: ~17 page boxes around the current page, with spacers (drawn as blank pages) for the rest. Pages mode uses `content-visibility: auto` on off-screen slots.
  - _Dark, Black and Sepia_ are baked into each bitmap with canvas blend modes (`difference` + `hue` for Dark and Black, `multiply` for Sepia), so there's no CSS filter for the compositor to re-run. iOS Safari has no canvas `ctx.filter`, which pdf.js's `pageColors` needs. Inverting would turn photos into negatives, so for Dark and Black the page's image placements are read from the operator list pdf.js already fetched for the render (`src/lib/pageImages.ts`) and each photo is copied back from the untinted render, clipped to its exact (even rotated) outline and dimmed slightly. A 24×24 sample tells photos from figures: a scan, chart or diagram that's mostly flat light background inverts with the page instead. Black (AMOLED) uses a pure #000 page and chrome.
- **Lookup modes** (Aa menu → Look up): _Wiki_ shows Owl's pill; _Safari_ shows no pill and never touches the selection, leaving iOS's own Copy | Look Up | Translate bar (which JS can't trigger); _Both_ shows the pill and restores the selection after the drawer closes so iOS's Look Up is still there.
- **Lookup cache**: entries older than 30 days are refetched when online (the old copy is still shown offline), the store is capped at 500 entries (least recently used go first), and cached cards have a _Refresh_ action. Wikimedia images load with CORS so the service worker caches real responses, not quota-padded opaque ones.
- **Lookup pill** fires on `pointerdown`, so the tap can't collapse the selection first, and sits in a fixed safe zone (bottom-centre portrait, bottom-right landscape) away from iOS's native callout.
- **Offline**: the app shell (including the pdf.js worker) is precached by Workbox. Lookups are cached in IndexedDB, and Wikimedia images are runtime-cached, so repeat lookups work in Airplane Mode. Maps need a connection.
- **Storage** (database icon in the Library header): space used via `navigator.storage.estimate()`, book and lookup counts, and _Clear Lookup Cache_ (with confirmation; books are untouched).
- **Updates**: the service worker uses `registerType: 'prompt'`; a _New version available — Update_ toast appears when a new build has installed (checked on start, hourly and when the app returns to the foreground).
- **Accessibility**: the lookup drawer, settings and dialogs are `aria-modal` with focus trapped (focus goes to the dialog, not a text field, so iOS doesn't raise the keyboard); PDF pages are labelled groups; `prefers-reduced-motion` turns off transitions and smooth page jumps.
- **Lookup context**: each book has a context tag (seeded from the PDF's Subject, or its title; editable under Aa → Book context). It is never added to searches automatically (a title like "The Gathering Storm" matches unrelated articles). For an ambiguous word, Owl reads the disambiguation page's own links (with descriptions and intros) and ranks them against the names on the current page: the X-Ray entities when opened from X-Ray, else the capitalised names near the selection. With no exact article, the bare word is searched. Below the drawer's search box, chips add the context or 1–2 capitalised names from near the selection in one tap. If the best search hit is a section inside a broader article, the card shows that section's heading and highlighted snippet, linking to the section. Not-found, disambiguation and section cards end with a _Search "{word} {context}" on Google_ link.
- **Clip & Export** (scissors in the top bar, or the scissors next to _Look up_ when text is selected): Clip Mode switches to the vertical layout for as long as it's open, without changing your Pages / Scroll setting. It drops a start and an end handle with a tint between them. You can scroll freely and drag a handle across page breaks, up to 5 pages, and handles snap to paragraph or line boundaries so a line is never cut in half. Only `{ page, y }` coordinates are kept while you clip, never bitmaps. _Export…_ offers: **Image**, where each page's band is rendered, running headers and page numbers are blanked, the empty margin at each page break is trimmed, and the bands are stitched with even spacing, with an optional Light / Sepia / Dark / Black theme and attribution footer, shared through the iOS share sheet (`navigator.share`) or downloaded; **PDF**, either _Cropped pages_ (the original vector pages copied with pdf-lib and cropped to the clip, so they stay searchable) or _Clean text_ (the passage re-set as a single page, so no page break splits it); and **Markdown**, a blockquote with headings, numbered lists and italics kept, line-end hyphens rejoined, a sentence split by a page break joined back up, and a citation line, which you can copy or download. _Save_ stores the clip, a few hundred bytes, in the `clips` store, and _Aa → Clips_ lists saved clips to jump to, export again or delete. Deleting a book deletes its clips. The overlay, exporters and pdf-lib are separate chunks: none of them load until you clip, and pdf-lib loads only when you make a PDF. They are precached, so export works offline.
- **X-Ray** (Aa → X-Ray: _Off_ / _This page_ / _Whole book_): _This page_ puts an X-Ray button in the top bar that lists the people, places, organisations and capitalised terms on the current page. Extraction runs in a Web Worker with [compromise](https://github.com/spencermountain/compromise) (rule-based, no ML model) plus a capitalisation heuristic for coined terms and acronyms; the worker and its code load only the first time X-Ray is used (about 70 ms from tap to list in emulation, including the drawer). _Whole book_ is per book: it indexes 10 pages at a time through the reader's idle queue (so it pauses while you scroll and never competes with page rendering) and checkpoints to the `bookIndex` store, so it resumes after the app is closed. Lookups of an indexed term then show an _In This Book_ card (first mention, every page as a jump pill) above Wikipedia, and a _Return to p. N_ pill takes you back. _Off_ runs no extraction at all and hides the button. Deleting a book deletes its index. Known gap: a name that only ever starts a sentence ("Sega paid…") is missed unless compromise tags it.

**PDF only since 1.2.** Books imported as other formats by 1.0/1.1 stay in IndexedDB untouched and show in the library as "Unsupported · tap to delete".

Not in 1.x, on purpose: accounts and sync, OCR for scanned PDFs, automatic (unasked) entity scanning, streaks and quiz export, PDF reflow, and the 2.x backlog (bring-your-own-key lookups, Book Atlas, breadcrumb trails, clean-text view).
